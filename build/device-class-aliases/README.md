# Device class aliases

Generated by `../GenerateDeviceClassAliases.sh` — do not edit by hand.

One file per xcframework whose **device** slice is missing exported `_OBJC_CLASS_$_<Name>`
symbols that its **simulator** slice has. Each line is one linker argument of the form

```
-Wl,-alias,<swift metadata symbol>,_OBJC_CLASS_$_<Name>
```

`Datadog.Binding.props` folds a framework's `.aliases` file into the `LinkerFlags` of its
`NativeReference`, so every consuming app's device link resolves the static registrar's class
references against the Swift metadata export — the very same class object the simulator slice
exports under both names.

Each affected framework also gets a `<Framework>Realize.xcframework` (generated source alongside
as `<Framework>Realize.c`): a static library holding one dyld initializer that realizes every
aliased class through its Swift metadata accessor (`_$s…CMa`). The metadata the aliases point at
starts out *unrealized* on device, and a cold Objective-C message to it is a segfault, not a slow
path — and the very first messages come from the static registrar's `xamarin_create_classes`,
called from `main()` before any managed code, so nothing managed can realize them early enough
(both facts measured on hardware). A dyld initializer in the app image runs after the Datadog
dylibs are loaded and before `main`, which is exactly the window. It ships as a second
`NativeReference` with `ForceLoad`, since nothing references the archive by symbol.

The asymmetry is an upstream defect in dd-sdk-ios's prebuilt archives: device slices are built
with a 12.0 deployment target, below which Swift withholds static Objective-C class
registration for classes whose metadata needs runtime fix-ups. See
`docs/release-notes/3.14.0.5.md` and the upstream report for the full story.

Regenerate after every `FetchXcFrameworks.sh` run and commit the result. When upstream fixes
its release pipeline these files disappear on regeneration and the props emit no flags. The
PackageTests symbol audit fails if the files drift out of date with `libs/`.
